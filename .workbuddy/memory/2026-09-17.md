## 一、RemoteControl 新增 network 模式（TCP 接入 MeArm-3D）—— 交付

- 新链路：`网页 → arm-web(netlink.Client) → TCP JSON Lines → MeArm-3D tcpserver → Controller → sim/real`。
  原两条链路（Web/串口、9002 透传）行为不变 —— 是**新增传输方式**，不是把串口改成 TCP。
- `start.bat`：默认 network；`--real`/`--serial` 走串口；`--network`/`-c FILE`/`--build`/`--no-build`/`--help`；
  **未知参数 exit 2**；每条退出路径都有 pause。
- MeArm-3D 侧**唯一**改动 = TCP v1 加**只读** `state`（不动 controller / device / IK / FK / MJCF /
  WS / HTTP / 前端）⇒ ADR **D83**。

**三条跨子项目经验**：

1. **同一条"推杆方向"在两条链路上不是一个意思**：serial 的 `invert_*` 含一层 arm-device 固件补偿，
   TCP 链路没有固件层 ⇒ 实测同满偏输入 **serial +90°/s vs TCP −90°/s**，而两边都"看起来正常"。
   修法 = 显式换算 `NetInvertFor` + 护栏测试（"满偏 dt=1s 的增量符号必须为正"），不靠目视。→ **已升为铁律 6**。
2. **"写命令齐全" ≠ 链路可用 —— 缺的是基准**：TCP v1 原全是写命令，增量式摇杆无从知道"现在在哪"。
   补**只读** `state` 远比在客户端猜起步角便宜；拿不到时降级 `fallback_angle` 并**显式上报**，不静默猜。
3. **被拒命令若不在本地回滚**，症状是"推杆完全不动且没有任何报错"；唯一可观测判据 = "被拒之后还能不能
   驱动该轴"，必须写成断言。

**零依赖浏览器取证（本机可复用）**：`npx` 撞 wsl 拦截，但本机 Edge 可 headless 出图 + dump DOM：
`msedge.exe --headless=new --disable-gpu --user-data-dir=<tmp> --window-size=1500,1050 --virtual-time-budget=7000`
再加 `--screenshot=<png>`（截图）或 `--dump-dom`（取 DOM，**重定向到临时文件再用 Grep 工具查**，本机 grep 不可信）
⇒ 可拿"按钮 `disabled` + 原因 title""面板可见性""实时数值已进 DOM"这类硬证据，不必下载 Chromium。

## 三、【定位 + 修复】TCP 驱动时 MeArm-3D 前端"幽灵动、主臂不动" → ADR **D84**

- **现象**（用户实测）：摇杆 → sim → 前端反馈通，但界面上动的只有**半透明幻影**，实体主臂不动。
- **根因**：前端画**两棵树** —— 主臂 = `commandJoints`（指令"要去哪"）、`ActualGhostArm` = `actualJoints`
  （实际"现在在哪"）；`transportBridge.handleState` 只在 `origin === 'device'` 时让**命令侧跟随**
  （写 `commandJoints` + 抑制回发），其余 origin 只写 `actualJoints`。协议注释里的原则是
  "**由谁引起，就由谁决定要不要跟随**"。而协议里**只有 `command` / `device` 两个来源，TCP 入口借用的是
  `command`** ⇒ 探针实测 **8/8 帧 `origin=command`、零帧 `device`**。
- **危害不止观感**：本页 `commandJoints` 停在旧位姿，用户下一次动**任何**滑杆，`transportBridge` 会把
  **整组 `commandJoints`** 下发（`sendJointState(commandJoints)`）⇒ 真机**跳回旧位姿**。
- **修法**：后端新增 `OriginExternal`；`Arm` 接口加 `ApplyFrom`；`move`/`gripper`/`servo` 三处改走
  `ApplyFrom(protocol.OriginExternal, …)`；前端 `StateOrigin` / `ORIGIN_EXTERNAL` 放行，`external` 与 `device`
  **同等对待**（跟随 + 抑制回发，防"命令→状态→命令"回环），`followExternal` 与 `followDevice` 共用
  `alignCommandSide` 但**日志文案分开**（外部入口不能报"设备侧自主变化"）。
- ⚠️ **两个易漏点**：① **来源必须随命令同行**（`curOrigin` / `pendingOrigin`）—— 不能等状态帧到了再从
  `inflight` 取，因为 `OK JR` 一到就 `finishInflight()` 清空 inflight，而后续 `STATE` 推进帧仍属于刚发出的命令；
  ② **前端有两层 origin 闸门**（后端常量层 + `WebSocketTransport` 白名单），只改一层 ⇒ 症状"后端标了、页面
  不跟随"，且 `tsc` 会顺带报 `TS2367 ... no overlap`。
- **顺带修掉自己验收脚本的真 bug**：`sim2sim-check.mjs` 注释写"从 HOME 附近出发保证可达"，代码却没在 XYZ 段前
  再 `goHome()`；而摇杆段位移按**真实 dt** 积分（跑一次一个值），底座一旦停在行程端点（实测 150°），`y±`
  必被 `ERR JOINT base ... (limit)` 拒 ⇒ **同脚本偶发 FAIL（一次绿一次红）**。
  修法：XYZ 段前显式回 HOME，并把它变成 1 项前置断言 ⇒ **29 → 30**。
- **新增两个可复跑判据脚本**：`MeArm-3D/core/tools/verify_external_origin.mjs`（后端侧 3 段对照）、
  `MeArm-3D/frontend/tests/e2e/external-origin-follow.mjs`（浏览器侧，headless Edge + CDP + dev 探针）。

**实测（本机，全在 Sim 链路上）**：后端 `go vet` 干净 / `go test` **114** 顶级用例 0 FAIL ·
前端 `tsc -b --force` 0 error / vitest **442**（33 文件）· `verify_external_origin.mjs` **3/3**
（A `command` 2 帧 · B `external` 6 帧 · C 回到 `command` 8 帧）· `external-origin-follow.mjs` **9/9** ·
Sim2Sim **30/30**。
关键读数：`commandJoints.base` 30 → −30，主臂末端位移 **114.97 mm**，`|tcp − actualTcp| = 0.000 mm`，
**渲染侧两棵树 TCP 世界坐标重合 0.000 mm**，日志出现「外部入口在驱动（另一台上位机 / TCP 网关）——
命令侧已跟随，未回发命令」且**零 SEND/joint_command**。
**变异测试（反证测试有效性，不是走过场）**：把 `commandOrigin()` 临时改成恒返 `OriginCommand`
⇒ 两条 controller 测试**如实变红**且报错直指根因；恢复后转绿。
**真机 `NOT TESTED`** —— 本轮全部验证在 Sim 上完成，未接真机。

**四条方法教训（都可复用）**：

1. **前端两层 origin 闸门**（见上，白名单是易漏点，已在注释里写死告警）。
2. **e2e 抓日志要认清通道**：来源提示走 `store().pushLog('in', …)`，落到页面右下角 `.log` 面板 ——
   **console 里一个字都没有**。第一版用 CDP `Runtime.consoleAPICalled` 抓 ⇒ 两个关键词都是 false，
   看起来像"文案写错了"，其实是抓错了通道。**判据要读 `.log`**。
3. **本机跑前端工具链不能用 `npm run`**：与 `bash` / `npx` 同源，会撞 **WSL 拦截**
   （`PROGRAM BLOCKED BY SECURITY POLICY: wsl.exe`）。要用 managed node 直调入口：
   `node node_modules/vite/bin/vite.js`、`node node_modules/typescript/bin/tsc -b --force`、
   `node node_modules/vitest/vitest.mjs run`。
4. **e2e 的确定性纪律**：`external-origin-follow.mjs` 第一版写死 `servo 1 120`，撞上上一轮残留位姿正好是 30°
   ⇒ 判据①假 FAIL。改成**反向驱动**（读基线 `base`，>0 发 60、否则发 120），保证每轮都有 ≥30° 变化。
