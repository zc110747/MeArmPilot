但是前端页面并没有同步状态，修复此问题，并移植到sim2sim链路(device代码已经重新烧录)`

### 两条结论（都可独立复核）

1. **real2sim 不是代码缺陷，是构建产物陈旧。**
   `MeArm-3D/backend/bin/armpilot-backend.exe` 停在 `09-15 19:03`，而 `09-16 17:15` 的提交
   改了 Go 源码却**没有重建** ⇒ 页面收不到（也不认识）`# SERVO` / `origin` / `device_command`。
   **判决证据**：对二进制做符号搜索，`device_command` / `ORIGIN_DEVICE` / `ReplyServo` **全 0 命中**。
   重建后：真机链路 **23/23** · 前端 DOM 读表 **9/9**。
   ⚠️ `start.bat` 的陈旧闸门只在**启动时**判"源码比 exe 新"，**救不了已经在跑的进程** —— 这次正是这个形式。

2. **sim2sim（此处指 MuJoCo 设备链路 `device.mode=mujoco`）对等落地。**
   `simulation/mujoco/server.py` 补齐 `SET` / `S<n>=` / `JOY` 三入口 + `# SERVO` 上报
   + `jr_busy`/`report_dirty` 让位闸门 ⇒ **22/22**（连跑 3 次稳定）；回跑 sim **23/23** 无回归。
   ⚠️ 该链路的收敛容差**必须**比另外两条宽（物理静态偏差，非缺陷）：见 ADR **D81**。

### 跨子项目可复用的两条

- **判"是不是陈旧构建"用二进制符号搜索**（`device_command` / `ORIGIN_DEVICE` / `ReplyServo`
  这类"新功能特有的标识串"），既不要看源码 mtime、也不要看进程启动时间。
- **`npx` 在本沙箱会触发对 `wsl.exe` 的拦截，且 stdout 会被打成乱码** ⇒
  取 vitest 计数改用 `node node_modules/vitest/vitest.mjs run --reporter=json --outputFile=<path>`
  落盘再读。同理：Bash / PowerShell 工具都拦 `cmd.exe`，要真跑 `.bat` 走 Python `subprocess`。
