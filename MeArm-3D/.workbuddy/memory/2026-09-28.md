### 关键设计取舍（回顾用）

- **v1 零改动是红线**。`move` 的参数校验**刻意留在原地**、全部先于取快照，
  只为保住错误优先级 `axis → direction → step 缺失 → step 非法 → 无位姿 → IK`。
  然后 `move` / `movexyz` / `moveto` 共用 `applyTargetLocked` 尾巴。
  判据：`TestMove_SingleAxisEqualsMoveXYZ`（六方向**逐位**比下发关节角 + `state.tcp`）
  + `TestV1Commands_UnchangedAfterV2`。
- **两条故意不对称的规则**（别在后续"顺手统一"）：
  ① `movexyz` 全零 delta = 参数错误（文本点明 `zero displacement`，手势静止帧应跳过）；
  ② `moveto` 的 `[0,0,0]` 是**合法**目标点，不可达该由 `OUT_OF_WORKSPACE`/`JOINT_LIMIT` 说。
- **`caps.workspace` 是外边界不是可达域**：由关节限位采样 FK 求出（n=12，1728 次），
  可达域是被限位切过的甜甜圈壳层，**盒内仍可能不可达**。只能做粗钳位。
- `caps.geom.reach*` 是**腕枢轴**的可达壳，不是 TCP 的（TCP 还要再水平前伸 `toolR`）。
- 写命令一律 `ApplyFrom(OriginExternal)`，与 v1 同源。

### 踩到的坑（可复用）

- **`gofmt -l` 在本仓会误报**：工作树文件是 **CRLF**，gofmt 只认 LF ⇒ 整文件"待格式化"。
  判真实差异要先 `tr -d '\r' > /tmp/x.go` 再 `gofmt -l`。**不要直接 `gofmt -w`**，
  会把全文件行尾换成 LF，diff 爆炸。本次 3 处真实问题手改解决。
- **Go 1.19+ gofmt 会重排 doc comment 里 `//    ` 的续行**（转成 `//\n//\t`）。
  挂在**声明**上的 doc comment 会被改写，文件顶部的自由注释不会。写新 doc comment
  时续行别加缩进。
- **`gofmt` 与 `git show` 的行尾不一致**：blob 是 LF、工作树是 CRLF ⇒ 拿 HEAD 版本
  直接 gofmt 对比会得出错误结论。
- **Go 侧 `Model.Joint(id)` 返回 `*Joint`（nil 表示找不到），不是 `(T, bool)`**。
- **`-race` 在本机全部包失败**（`exit status 0xc0000139`，缺 race runtime DLL），
  连未改动的包也一样 ⇒ 环境限制，不是代码问题。别当成回归。
- **Bash 工具里 `cmd &` 起的进程活不过该次调用**，要用 `run_in_background=true`。
- **Edit 的 old_string 里中文 box-drawing 字符（`─`）个数极易数错**导致匹配失败。
  挑锚点时选 ASCII 或短唯一串（如 `        c2.close()`），别赌连续 `─` 的个数。
